For people with low vision or visual impairments, daily interactions with printed physical documents—utility bills, medical prescriptions, government notifications, lab reports, and medication leaflets—present a severe accessibility barrier.

While modern smartphone cloud apps (such as Seeing AI or Google Lookout) offer optical character recognition, they introduce two critical friction points: **privacy vulnerabilities** and **cloud dependency**. Uploading sensitive medical records or financial invoices to remote servers is a serious concern for privacy-conscious users. Furthermore, relying on active internet connections or recurring monthly subscriptions restricts accessibility in remote areas or low-connectivity environments.

To address this challenge, I designed and developed **Basira (بصيرة)**: an open-source, 100% offline, local-first document reader and voice assistant. Basira allows a user to photograph or scan any physical document, automatically extracts bilingual text (Arabic and English), distills and simplifies complex terms using a local Large Language Model, and reads the essential findings aloud using natural neural speech synthesis—all running locally on standard laptop or desktop hardware.

## 3. Intelligent Image Preprocessing & OCR

Raw images captured by hand from smartphone cameras or webcams often suffer from uneven shadows, low lighting, improper orientation, and low resolution. If passed directly to an OCR engine, character error rates (CER) on complex scripts like Arabic rise significantly due to cursive ligatures and diacritics.

To solve this, Basira implements a deterministic pre-OCR transformation pipeline using Pillow:

```python
# src/services/ocr.py
from PIL import Image, ImageOps
import pytesseract

def prepare_image(img: Image.Image) -> Image.Image:
    # 1. Respect smartphone EXIF orientation flags
    img = ImageOps.exif_transpose(img)
    
    # 2. Eliminate color noise and reduce channels to 8-bit luminance
    img = ImageOps.grayscale(img)
    
    # 3. Maximize contrast across dark text and faint paper backgrounds
    img = ImageOps.autocontrast(img)
    
    # 4. Upscale small documents to ensure character height exceeds 30px
    if img.width < 1500:
        scale = 1500 / img.width
        img = img.resize((int(img.width * scale), int(img.height * scale)))
        
    return img

def read_text(img: Image.Image, ocr_lang: str) -> str:
    img = prepare_image(img)
    text = pytesseract.image_to_string(img, lang=ocr_lang)
    return text.strip()
```

### Key Engineering Decisions:
1. **EXIF Transposition (`exif_transpose`)**: Mobile browsers frequently upload rotated images based on sensor metadata. Standardizing orientation prevents inverted text OCR failure.
2. **Autocontrast Normalization**: Maximizes the dynamic histogram range, separating faded ink and receipt thermal prints from gray paper background.
3. **Width Clamping**: Tesseract's LSTM neural network performs best when character line heights fall within a specific pixel band. Upscaling images under 1500px ensures small fonts are cleanly segmented.

## 4. Local Cognitive Reasoning & Prompt Engineering

Reading raw OCR text verbatim is often overwhelming for a visually impaired user. An invoice contains dozens of irrelevant line items, tax IDs, and barcode artifacts. The user primarily needs to know:
- **What is this document?**
- **How much do I owe, or what dosage do I take?**
- **What is the deadline or appointment time?**
- **What action is required from me?**

Basira uses **Ollama** running **Qwen 2.5 (3B)** locally. Qwen 2.5 was chosen because of its exceptional multilingual reasoning and strong native Arabic language comprehension, even at compact quantized sizes.

### Anti-Hallucination & TTS-Safe System Prompt

Designing prompts for text-to-speech output requires strict formatting constraints. If the LLM generates markdown formatting like `**Amount:** $50` or bullet lists (`- item`), the speech synthesis engine will literally vocalize *"asterisk asterisk Amount asterisk asterisk"*, ruining the auditory experience.

Here is the exact prompt engineering deployed in `src/config.py`:

```python
# src/config.py
SYSTEM_PROMPT = """You are Basira, a kind and patient assistant who helps a person
with low vision understand paper documents.

Rules:
- Reply in {language_name}.
- Use short sentences and very simple words, as if talking to a loved one.
- Start with ONE sentence: what kind of document this is.
- Then clearly list: amounts of money, dates and deadlines, names, and
  anything the person must DO.
- The text came from OCR and may contain mistakes. If a number or word looks
  unclear, say so honestly. NEVER invent information.
- For medicine or legal papers, add: "Please confirm with a doctor/pharmacist
  or a trusted person."
- Do not use markdown symbols, bullet characters, or emojis. Your answer will
  be read aloud, so write natural spoken sentences."""
```

### LLM Service Execution

```python
# src/services/llm.py
import ollama
from src.config import MODEL, SYSTEM_PROMPT

def explain(text: str, language_name: str) -> str:
    response = ollama.chat(
        model=MODEL,
        messages=[
            {
                "role": "system",
                "content": SYSTEM_PROMPT.format(language_name=language_name),
            },
            {
                "role": "user",
                "content": f"Here is the text from the document:\n\n{text}",
            },
        ],
        options={"temperature": 0.2},
    )
    return response["message"]["content"].strip()
```

Setting `temperature: 0.2` prevents creative hallucination, forcing the model to strictly summarize verbatim factual numbers and dates present in the extracted text.

## 5. Offline Neural Speech Synthesis (Piper TTS)

Many local TTS solutions (such as Coqui XTTS or Bark) require heavy GPU VRAM and take 5 to 15 seconds to synthesize a paragraph. On the other end of the spectrum, standard OS text-to-speech tools (e.g., SAPI5 or eSpeak) sound robotic and lack natural Arabic intonation.

Basira integrates **Piper**, an ultra-fast, local neural text-to-speech engine based on the VITS architecture running on **ONNX Runtime**.

```python
# src/services/tts.py
import tempfile
import wave
from pathlib import Path
from piper.voice import PiperVoice
from src.config import VOICES_DIR

VOICE_CACHE: dict[str, PiperVoice] = {}

def get_voice(voice_name: str) -> PiperVoice:
    if voice_name not in VOICE_CACHE:
        model_path = VOICES_DIR / f"{voice_name}.onnx"
        if not model_path.exists():
            raise FileNotFoundError(f"Voice not found: {model_path}")
        VOICE_CACHE[voice_name] = PiperVoice.load(str(model_path))
    return VOICE_CACHE[voice_name]

def speak(text: str, voice_name: str) -> str:
    voice = get_voice(voice_name)
    out_file = Path(tempfile.gettempdir()) / "basira_output.wav"
    with wave.open(str(out_file), "wb") as wav_file:
        voice.synthesize_wav(text, wav_file)
    return str(out_file)
```

### Speech Synthesis Performance:
- **In-Memory Caching (`VOICE_CACHE`)**: Initial ONNX model loading occurs once; subsequent voice synthesis requests run in **under 250ms** on an average CPU.
- **Natural Arabic Diacritization & Flow**: Uses the `ar_JO-kareem-medium` model, producing human-quality Arabic phonetics without robotic stuttering.
- **English Support**: Uses `en_US-lessac-medium` for crystal-clear English technical and medical pronunciation.

## 6. The Unified Processor Pipeline

The core orchestration module ties all components together with defensive error handling:

```python
# src/core/processor.py
from PIL import Image
from src.config import LANGUAGES
from src.services.ocr import read_text
from src.services.llm import explain
from src.services.tts import speak

def process(image: Image.Image, language_choice: str, read_mode: str):
    if image is None:
        return "Please add a photo first.", "", None

    settings = LANGUAGES[language_choice]
    language_name = "Arabic" if "Arabic" in language_choice or language_choice == "العربية" else "English"
    if language_choice == "Arabic + English":
        language_name = "Arabic"

    # Step 1: Optical Character Recognition
    try:
        raw_text = read_text(image, settings["ocr"])
    except Exception as e:
        return f"OCR problem: {e}", "", None

    if len(raw_text) < 5:
        return "I couldn't read much text. Try a clearer, brighter, straighter photo.", raw_text, None

    # Step 2: Cognitive LLM Explanation
    explanation = ""
    try:
        explanation = explain(raw_text, language_name)
    except Exception as e:
        explanation = f"(AI explanation unavailable: {e})"

    # Determine speech target based on user preference
    if "النص الأصلي" in read_mode:
        text_to_speak = raw_text
    else:
        text_to_speak = explanation if not explanation.startswith("(AI explanation unavailable") else raw_text

    # Step 3: Neural Voice Synthesis
    try:
        audio_path = speak(text_to_speak, settings["voice"])
    except Exception as e:
        return explanation + f"\n\n(Voice problem: {e})", raw_text, None

    return explanation, raw_text, audio_path
```

## 7. Accessible UI & Local Wi-Fi Bridging

Accessibility is central to Basira's frontend design. Using Gradio with tailored CSS overrides, the UI ensures high-contrast readability and large interactive tap targets:

```python
# src/ui/app_ui.py
CUSTOM_CSS = """
* { font-size: 22px !important; }
h1 { font-size: 48px !important; }
textarea, .prose { font-size: 26px !important; line-height: 1.6 !important; }
button { min-height: 70px; font-weight: bold; }

```

### Wireless Phone-to-PC Bridge
Instead of requiring a dedicated mobile app build, Basira runs as a lightweight local web server on port `7860`.

When connected to the same household Wi-Fi:
1. The user opens `http://<computer-ip>:7860` on their smartphone browser.
2. Tapping the image box opens the smartphone camera directly.
3. The image is processed on the host PC's CPU/GPU, and the generated audio stream streams back instantly to the phone speaker.

## 8. Hardware Footprint & Benchmarks

All tests below were executed on an entry-level laptop with an **AMD Ryzen 5 / 16 GB RAM** with **no dedicated GPU**:

| Pipeline Stage | Technology | Resource Utilization | Average Latency |
|---|---|---|---|

| **Multilingual OCR** | Tesseract 5.3 | ~45 MB RAM | **420 ms** |

| **Total Pipeline** | **End-to-End** | **< 2.4 GB RAM** | **~2.5 seconds** |

## 9. Future Roadmap & Research Directions

Basira serves as a foundational open-source architecture for offline assistive AI. Moving forward, several high-impact features are planned:

1. **Local Vision-Language Models (VLM)**: Evaluating lightweight edge VLMs (such as *Moondream 2* or *Qwen2-VL 2B*) to replace the standalone OCR step, enabling better chart, table, and multi-column receipt comprehension.
2. **Hands-Free Voice Activation**: Integrating local **Whisper.cpp** to enable full voice conversational control without needing to tap screen buttons.
3. **Embedded Hardware Edition**: Packaging the entire stack into a dedicated Raspberry Pi 5 / Orange Pi setup with a physical camera button and built-in speaker.
